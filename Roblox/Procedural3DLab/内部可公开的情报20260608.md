# 一句话定位

JSON 驱动的 3D 角色/资产**程序化**生成工具链,目标是让 AI / 编辑器 / 引擎用同一份纯数据描述角色 与 游戏物体,在 Three.js 等任意 引擎运行时复现一致的外观。不是游戏,是底层管线。

# 交付物
| 类别      | 对应交付物 |
| ----------- | ----------- |
|动态物体比如角色 |描述Json+SDK+个性化Skin PNG|
|静态物体|计划1：1个或几个js方法，生成模型的，生成/拿本地贴图的，资源上体现为代码块 计划2：SDK版本中也包含一份|

# 设计取舍
| 选择      | 取舍 |
| ----------- | ----------- |
| JSON 是真相源 & 引擎无关     | 不存二进制 mesh,所有形状由SDK代码 + 参数生成       |
| 移动端优先   | 低 draw call、低材质、低三角面;mobile budget 在 validator 模块 里强校验        |
|  AI 友好   |   Schema 严格、确定;LLM 可以生成合法 JSON    |
|  参考Roblox角色 和 Slot插槽设计   |  类似Roblox的模型结构、可设计的Skin、Slot定位其他模型  |

# 已完成
在物品和角色中，选择先做好角色，因为感觉角色比较难做，角色更有表现力。
## 数据层
+ Schema作为AI生成Json约束。Validator模块校验。
+ MajiFigure 默认角色规范 - 20块骨骼\手部Slot\T-pose
+ Web预览，可以看模型效果、三角面材质dc等等信息。
+ 五个模块 schema / core / validator / three-renderer / three-browser-runtime

## 程序生成层
零外部模型，所有物体、角色部件都用程序生成。

## 皮肤层
+ 包含身体、腿、面部 3个静态Skin，用png、webp等任意的512*512、256*256图片。
+ 包含默认的皮肤
